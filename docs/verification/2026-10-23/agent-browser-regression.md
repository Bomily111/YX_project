# 智能体浏览器回归门槛

日期：2026-10-23。`scripts/verify-langchain-browser.mjs` 现在对四类场景做明确断言：TSP 坚硬度与结构树支护同屏装配、TEM 单资源装配、缺少目标里程时追问、只生成计划而不执行。检查目标 YK 里程、页面资源、任务运行记录数量、模型接口状态、Cesium 画布与页面错误；平台报告加载失败时判为失败。脚本设总时限，避免三维资源加载挂起使回归无限等待。

本地 DeepSeek/LangChain 页面实跑结果：缺里程用例通过，没有创建任务；只规划用例通过，创建一条 `ready` 计划记录，但没有装配场景。TSP 坚硬度与支护组合用例创建了任务，却在加载 `tsp_hardness` 体数据时超时，页面报告“场景装配未完成”，回归正确退出失败。TEM 用例在无头浏览器中长时间无结果，已中止；本轮不能宣称其装配通过。这两类三维资源问题应在可交互、硬件渲染的浏览器中继续排查，不能归因于模型资源选择或提示词。

运行示例：`$env:BROWSER_SCENARIO='missing-mileage'; node scripts/verify-langchain-browser.mjs`。其余场景为 `plan-only`、`tem`、`hardness-support`；可用 `BROWSER_TIMEOUT_MS` 调整总时限。需要本地 Vite 页面和 DeepSeek 后端在运行。

后续排查修正了 ShareVolume 体纹理加载时先设置 `image.src`、后注册 `onload` 的竞态，并对请求失败、图片解码失败写出明确日志；Blob URL 在成功或失败后释放。TSP JSON 和纹理文件存在，Vite 对纹理 HEAD 返回 200。相关 16 项单元回归通过。修正后无头浏览器内的 TSP 组合任务仍超过 90 秒总时限，因此这项竞态修复尚不能视作体数据超时的完整解决方案；后续应采集浏览器 WebGL 能力、纹理请求和 ShareVolume 初始化错误，使用硬件渲染页面验证。

继续定位：新增 `scripts/diagnose-volume-browser.mjs`。无头 Edge 报告 WebGL 1.0、最大纹理尺寸 8192；TSP JSON 和 `hardness_volume.png` 均收到 HTTP 200。25～30 秒采样时 `volume-canvas` 已存在，ShareVolume 构造耗时约 0.4～0.6 秒，但聊天仍未完成，状态仍显示 `Loading image data...`。因此文件缺失和构造函数长期阻塞已排除；剩余问题可能在渲染就绪状态传递或后续绘制循环，尚需进一步定位。诊断脚本设硬时限，避免页面挂起导致命令无限等待。

进一步修复与复验：ShareVolume 在体渲染器建立后直接通知 GeoModelController 就绪，平台任务不再仅依赖受重绘影响的 100ms 轮询；保留 15 秒超时。TSP 坚硬度＋支护组合的真实无头页面回归现以一次任务创建通过，左侧显示 YK1+346 与两类资源，模型答复保留源工点和示意重定位说明。TEM JSON 和纹理同样返回 200，渲染器可建立，但原配置的 256 次采样和三次插值令软件 WebGL 持续卡顿；将该 TEM 显示配置降为 128 次采样、线性过滤后，YK2+244 的单资源装配回归也通过。TEM 数据值和纹理文件未改，资产清单已更新对应 JSON 指纹。两例仍需在交互式硬件浏览器做画面质量与三维可见性复核。

在线决策基线新增 6 个明确资源任务（设计分级、融合分级、TSP 坚硬度、TSP 完整度、TEM、结构树单独钢架）和 3 个不应执行装配的任务（缺里程、双候选里程、只规划）。DeepSeek/LangChain 在相同提示词下连续 3 轮全部通过，合计 27/27 个模型决策判定；该结果只测工具选择与参数，不代表资源装配或三维像素正确。全量离线回归 166 项通过、在线用例按默认配置跳过。

尝试在无头浏览器装配后直接截取页面时，截图步骤偶发使软件 WebGL 页面超过总时限。截图没有并入通过门槛；交互式硬件浏览器仍需补画面证据。页面回复与任务快照写入之间存在短暂的异步状态，回归会轮询数据库终态，不以工具提示是否消失作为装配完成条件。

随后加入数据库回读断言，要求最终快照为 YK 坐标系、所有步骤完成、根资源为 `loaded`，且记录源 JSON 和体纹理的资产版本。首次 TSP＋支护复验虽然无头页面超时，数据库实际为 `completed 2/2`、9 个资源已加载；这表明调度与装配已执行，剩余波动在浏览器渲染或页面响应。将 TSP 坚硬度展示采样数由 256 调至 128，并令体渲染循环仅在相机、画布尺寸或渲染器变化时提交绘制后，TSP＋支护页面回归通过：左侧显示 YK1+346 和两类资源，数据库回读为 `completed 2/2`，9 个资源加载，TSP JSON、PNG 与 9 个支护 GLB 路径均已保存。TEM 页面回归通过：YK2+244、数据库 `completed 1/1`、TEM JSON 与 PNG 路径已保存。原始体纹理和数值没有修改；TSP 的展示配置及资产清单已同步更新。

这两例验证了对话发起、DeepSeek 工具选择、平台自主调度、资源加载状态、侧栏呈现与持久化快照的连通性；Cesium 画布存在，但尚无可靠的像素级画面检查。无头软件 WebGL 对复杂体数据和大量支护 GLB 的性能仍可能波动，应以交互式硬件浏览器补充画面质量复核。

重复 TSP＋支护时，1600×900 的无头软件 WebGL 页面仍有一次 90 秒超时；同次数据库轮询明确读回 `completed 2/2`、9 个资源加载。回归窗口改为 1100×720 后，组合任务再次通过页面与数据库双重检查。这是降低测试环境的渲染负担，不能据此宣称全尺寸或硬件浏览器的帧率。缺里程用例再次通过，未创建任务；只规划用例再次通过，数据库为 `ready 0/1`、没有加载资源。

围岩解释资源扩展回归：TSP 完整度在 YK2+244 的页面装配通过，数据库 `completed 1/1` 并保存完整度 JSON 与 PNG 指纹。融合围岩等级首次同样出现无头页面超时，但数据库已是 `completed 1/1`；其默认展示 JSON 仍为 256 次采样。将智能体默认使用的 `fused_rock_grade_2345.json` 调至 128 次采样并更新资产清单后，页面和数据库双重检查通过，保存融合等级 JSON 与 PNG 指纹。其他融合等级筛选变体仍保留原显示参数，需要单独验证其交互性能。

设计围岩等级也完成真实页面回归：YK1+346、`rock.design-grade` 与公共隧道资源加载，数据库 `completed 1/1`，快照保存三段隧道 GLB 路径。至此设计分级、融合分级、TSP 坚硬度、TSP 完整度、TEM 五类围岩资源都有至少一次端到端装配证据；其中支护组合同屏任务为两阶段。它们是示意场景装配的连通性证据，不等同于不同来源地质结果的同工点联合解释。

另测单独结构树钢架：在线模型两次都只选 `support.legacy-steel-frame`，数据库均为 `completed 1/1`，实际加载根资源仅此一项，源 GLB 路径正确，没有误装配整套支护。无头软件 WebGL 页面在 1100×720 和 800×600 都超过 90 秒，故该用例目前只有工具选择、平台执行和数据库证据，没有通过页面呈现门槛。后续需在硬件浏览器核对该 89 榀既有钢架的实际可见性和交互响应。
