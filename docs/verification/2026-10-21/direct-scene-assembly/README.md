# 主场景单入口自主装配验收（2026-10-21）

## 目标与实现

针对普通场景请求，模型只选择目标资源与目标里程，调用一次 `assemble_scene_at_mileage`。工具以用户原话核对唯一 DK/YK 里程，平台校验资源覆盖范围、同屏规则、依赖与预算；随后从中线数据定位主 Cesium 场景，按内部受控步骤加载资源。模型不再自行串联准备、推进、修订、飞行和单模型加载工具。

主页面的聊天窗口改为右侧栏。任务成功后，左侧与底部展示目标里程、实际装配资源和任务状态摘要；完整任务面板改名“任务运行记录”，由用户按需打开。左/底信息目前是可核实的二维状态摘要，尚无围岩、支护业务曲线或图表。

## 真实页面与数据库验证

在本地页面点击快捷请求“在 DK278+330 主场景同屏装配设计围岩与支护钢架”。在线 Ollama/Qwen 调用了一次 `assemble_scene_at_mileage`。右栏返回“已定位 DK278+330，主场景装配完成：围岩设计分级、支护钢架示例”；左/底摘要出现同一目标和两类资源。三维视口可见中线附近的设计围岩与支护示例，镜头经过右栏占位调整后保留主要场景在可见区域。

任务 `scene-1792559505673-05zov` 的审计轨迹依次为：`create_task`、`execute_task_step(scene-1)`、`execute_task_step(scene-2)`、`assemble_scene_at_mileage`；模型侧只有最后一项工具调用，前面三项由平台内部完成。PostgreSQL 快照 ID 124、125、126 分别记录准备、围岩完成、围岩加支护完成；最终实际根资源为 `rock.design-grade,support.scene`，第二阶段里程为 `278330`。

复测前发现模型将明确的 `DK278+330` 传成非 DK/YK 格式，单靠工具 Schema 无法保证参数正确。入口现从用户原话提取唯一里程；未给里程或给出多个不同里程时拒绝装配，避免模型猜测位置。

全量前端回归 25 个文件、148 个用例通过；资产清单 57 项校验和生产构建通过。

## 边界

现有钢架是平台示例资源，外部完整参数化支护模块仍待交付。目标里程必须处于每个资产实际覆盖范围；原结构树 GLB 保留其 DK278+100～167 布置，不能当作 DK278+330 资源迁移。左/底摘要不提供工程结论；未来若增加二维图表，应使用模型或业务数据的真实读数。装备调度尚未接入。
