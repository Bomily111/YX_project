# 智能体自主调度原型验收

日期：2026-10-19。本轮目标是让智能体按任务目标构建和可视化场景，并让表单/自然语言两种任务入口共用校验和执行链。

- 对话内表单输入逆序里程 `278340 → 278330`，平台返回 `chainageRange` 规则错误，没有生成执行入口；改为 `278330 → 278340` 后校验通过，显示两步计划，并在对话中自主执行到 `2/2`。截图：[表单对话](form-chat.png)。
- 表单选择“场景构建与展示”，依次添加围岩设计分级和结构树既有支护组合，经同一校验链生成两步计划，作为智能体资源选择的人工对照。截图：[场景表单](scene-form.png)。
- 本地 Ollama/Qwen 2.5 7B 对“围岩→既有支护，自主构建并展示”选出 `rock.design-grade` 和 `support.legacy-assembly`。平台执行 `scene-1 → scene-2` 后状态为 `completed 2/2`；既有支护仍位于结构树原示例段，不是 DK278+330 实测支护。截图：[自然语言场景调度](scene-chat.png)。复位后两类任务资源均为 `idle/0`、增强计划与指令为 0，公共隧道保留原有 `loaded/1`。
- 初次真实模型试验选择了仅生成计划的旧工具，虽然用户明确要求执行。新增意图路由后复验完成闭环；审计同时保留 `modelTool=compose_scene_workflow` 与平台实际 `orchestrate_platform_task`，可用于实验区分模型行为与护栏行为。
- [轨迹样本](trajectories.jsonl) 从 PostgreSQL 导出，包含目标、模型选择、资源序列和逐步结果。当前只有 2 条合格样本，尚不足以训练或评价模型。

验证：25 个测试文件、132 项通过；49 文件资产指纹清单校验与生产构建通过。模型自主选择与执行已在真实页面验证；尚未做训练、跨任务泛化或消融实验。装备调度版块未参与。
