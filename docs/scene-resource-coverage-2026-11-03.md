## 下一批实施顺序

1. 对新增 TSP/TEM 属性层逐项做实际画面、切换释放和来源提示验收，确保数据库记录的是实际显示的属性文件。
2. 将掌子面照片、GPR、超前水平钻、TEM 异常体按“施工任务语义 → 坐标配准 → 资源适配器 → 白名单 → 页面回归”逐类接入。
3. 支护改为按工段/任务选择断面类型和连续长度，复用支护模块现有构件；明确 Z-PM 部分断面的适用边界。
4. 通风多工况/时间片与爆破设计信息进入对话调度；再验收围岩、支护、通风、爆破的跨阶段保留、切换与最终场景。
5. 固化构建结果并单独开展构建后增强；数据库资源目录可逐步替换当前静态白名单，GLB 和体纹理仍由文件存储提供。

本轮页面实测：`co`、`tsp-vp`、`tem-water` 三个场景均 `completed 1/1`，PostgreSQL 回读到各自实际资源和源文件指纹。新增体数据的画布容器可见；无头软件 WebGL 的逐像素质量仍需另行验收。

追加页面实测：`vent-flow` 复用通风版块已有 `buildSteadyLayers`，加载 CFD 点云、风向矢量、风场流线和动态粒子四类图层；`blast-cloud` 返回炮孔与点云复合 GLB，两个任务均 `completed 1/1` 并保存资产指纹。通风流线的生成方式沿用现有版块实现，本轮仅验证主场景复用与图层状态，未重新评价 CFD 计算方法。爆破点云为现有 GLB 内的几何节点，不需重复导入原始 LAS。

通风后续数据的接入格式和配准要求见 [通风新数据交付与接入约定](ventilation-data-handoff.md)。现有两份稳态 CFD JSON 已接入运行时结构校验，保留 `meta.n` 与实际 6786 项不一致的提示；校验不改动原始样本。
