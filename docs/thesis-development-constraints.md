## 3 必须保持的技术路线

1. **任务与资源组织**：整理既有围岩解释、爆破、结构树支护、通风等资源的语义、空间范围、来源、能力和输入条件；以工地真实中线及统一里程为公共空间基准。图2列出五大场景，但正文P0173—P0174明确调度待接入，不把五类均完整接入当作既成事实。
2. **智能体自主装配**：自然语言需求 → 目标对象/里程/资源/约束 → 智能体调用规划 → 平台结构、空间与兼容规则校验 → 依赖加载及沿中线定位 → 实际结果、失败回滚和受控修正。不能让模型口头完成替代实际执行，也不能把主线场景规划整体替换为关键词硬编码；规则用于边界、路由及确定性校验。
3. **任务自适应增强**：结合任务、已装配对象与需保留的空间参照确定重点 → 智能体选择受控视觉策略或组合 → 平台执行 → 读取实际生效状态 → 评价辨识与理解效果，必要时有限调整并恢复。视点、显隐、透明度、剖切、重点标识和来源区分须服务具体问题，不是每次机械套用同一效果。
4. **原型与试验**：同一Cesium Viewer集成。开题原文方案为Vue 3/Cesium/ECharts、DeepSeek经LangChain产生工具调用，工作流和资源管理器确定性执行、审计和快照（P0154、P0157）。常规改进沿现有架构，不无故换技术栈、拆多个Viewer或扩成通用智能体平台；确需调整时说明对研究路线的影响。
5. **连续分析**：重点切换时保留必要背景、对象关系和前序依据；任务结束或切换时正确释放资源并恢复表达（P0128、P0155）。仅进入步骤、点击对象或打开来源不代表分析问题已经解决。

## 4 范围控制与不优先开展的工作

以下是依据原文及用户本次要求制定的执行规则，不冒充报告逐字规定。

- 每项工作归属R1、R2或R3，并绑定一个可运行的施工任务、现存问题及可观察的改进。不能说明对应关系的功能不进入当前开发。
- 新工具、字段、日志、证据卡和摘要仅在修复真实错误或支撑已选方法/试验所必需时增加。现有记录与引用链已有基础，暂停无具体方法需求的继续扩写，不另建通用证据管理系统。
- 模型补建按用户授权作为支线：只有代表性任务确实缺少必要对象时才做，优先复用；保留建模来源、脚本和示意参数。不以继续增加三台阶变体、设备或场景数量当作主线交付。
- 不主动扩张为全面装备调度、通用项目管理、任意知识图谱、多智能体平台、跨会话长期记忆、完整文档管理或全工程重建。开题图中出现模块/文献方法，不等于必须全部实现。
- 二维三维联动、任务文字依据与建议是原文信息理解方向上的具体实现及后续用户补充；按代表任务需要做。原文未单独要求庞大检索系统、任意问答或自动质量验收，不能把这些设成全部增强工作的先决条件。
- 报告P0157说明已有设计资料基础；当前代码未接入正文不代表工程没有设计文件。优先核实已有资料与接入范围，不能凭缺省字段声称现实资料不存在，也不能补造条文、页码、实测或偏差。
- 保留全部未提交改动，不为收敛范围擅自删除已有能力或历史证据。不改原始工程数据以制造贴合或美观效果。

## 5 用户补充要求与场景质量底线

以下来自此前用户确认的开发计划与本次纠偏，作为工程实施要求保留：全场景准确性、真实性、美观性与可读性整治；三台阶与后方支护作为首个样板；任务相关二维三维及文字依据协同；自主真实页面测试、保留未提交改动、不逐步确认。

2026年11月17日最新显示要求：测试工段继续依据主页面真实中线和统一里程装配；地形与影像沿用主页面当前设置。不得在装配完成后自动压暗影像、去色或强制将地形淡为黑底。地下细部和地理位置可切换取景，不能把调整显示当作修改工程位置。

源几何、方向、比例、标高和接缝问题应修复或明确界定适用范围，不能用透明、遮挡、缩放或取景隐藏错误。资源加载、模型ready、包围球入镜、实际可辨认、工程判断成立是不同层次。自动化成功率不能证明审美、认知或工程有效性。

资料不足时可在明确示意范围内推进视觉方法与受控试验，不无限增加“资料缺失”记录来代替方法开发，也不以缺少正式正文为由停掉所有视觉工作。

## 6 实验必须对应原文

依据P0155及图2建立固定任务集，首先覆盖已有围岩解释与结构树支护、不同里程、单/多资源同屏及错误请求。固定任务、资产、数据版本、视口和必要的显示条件，比较：

| 条件 | 用途 |
|---|---|
| 人工操作 | 装配与分析操作基线 |
| 智能体自主装配 | 衡量R1的贡献 |
| 自主装配并启用增强 | 在相同装配基础上衡量R2的额外贡献 |

装配指标包括需求识别、资源选择、里程定位、规则校验通过率、实际装配成功率、错误/重复调用次数、完成时间。增强指标包括任务耗时、场景切换次数、关键对象识别正确率和信息理解。分别关闭遮挡处理或重点标识做消融，并测试切换、回看、退出后的释放与恢复。

必须区分系统回归、几何/画面诊断、人员任务实验；长时稳定性和测试条数不能替代认知效果。样本量、阈值、人员背景、学习顺序及统计方法在试验前明确，不预先编造显著提升。二维联动消融等属于总计划补充，应标明扩展，不冒称原文全部明定。

原文P0163—P0168的时间表保留为论文阶段安排，不擅自修改日期，也不将其理解为现在不能提前开发。

## 7 每轮开发的最小核对

开始前在工作记录中用简短文字回答：对应R1/R2/R3及原文章节；本次施工任务与具体问题；预期可观察改进；最小改动范围；验证方式与停止条件。可合并成一个短段落，不要求每次另建一份文档，不增加用户确认流程。

优先完成一个“任务—方法—实际效果—验证”闭环。若中途仅剩新增记录、工具或非必要模型可做，应回到已识别主线缺口；真实阻塞时如实说明，不用支线充当主线进展。遇到实际故障可做必要修复，但不借机扩张架构。

结束时报告：改了什么、对应哪项研究内容、实际验证结果与适用限度、仍未解决的问题。明确“基础能力完成”“方法实现”“效果已验证”三种状态，不把工具调用成功称为方法或论文目标完成。
