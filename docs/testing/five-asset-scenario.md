# 五类现有资产的跨模块场景测试

日期：2026-10-17

## 目的与边界

使用真实的公共隧道 GLB、围岩设计分级、参数化支护钢架、爆破点云 GLB 和通风 CFD/流线数据，检验现有资产能否支撑分阶段展示及跨模块切换。此测试验证**资产可用性、场景展示与资源生命周期**，不验证爆破设计或通风安全计算的工程正确性，也不将不同里程段硬叠成同一掌子面。

围岩、支护和爆破共用 `tunnel000.glb` 所在的 DK278+330 附近场景；通风模型由独立局部工程坐标锚定在同一工程区域的另一段，测试时切换视角与资源。支护钢架由参数生成，无静态钢架 GLB 文件。不得把这一测试称为五种模型已完成统一时空配准。

## 自动化资产门槛

在项目根目录运行 `npm run test:scenario`。测试直接读取现有文件，检查：

1. `tunnel000.glb` 的 glTF 2.0 结构，以及设计分级在任务里程 `DK278+330–340` 能给出 V 级结果。
2. 当前 `I16` 参数能生成非空、尺度合理的支护钢架几何。
3. `blast_effect.glb` 含实际 450000 点的 POINTS 图元，不只是预览贴图。
4. 通风专用 GLB 与 CFD 数据存在，位置/速度数组同长且有有效速度值。
5. 三个关键 GLB 的字节哈希与任务资产清单一致。

已知数据质量问题：`cfd_cell_data_lite.json` 的 `meta.n` 为 6785，但各采样数组长度为 6786。渲染逻辑按数组长度遍历。自动化测试将元数据一致性标为**预期失败**，保留显式告警；拿到可信的原始 CFD 导出后应校正元数据并把该用例改成普通通过用例，不能为了让测试通过而删除一个采样点。

## 浏览器三维验收

在开发态同一浏览器会话中依次执行，并在每阶段保存截图及 `window.__DT_PLATFORM_DIAGNOSTICS__?.()` 的结果：

| 阶段 | 操作 | 通过条件 |
|---|---|---|
| 基线 | 打开首页，记录诊断快照 | 只有一个 Viewer/Canvas，资源无失败状态 |
| 围岩 | 首页任务流程生成并执行 `DK278+330–340` 质量检查的围岩步骤 | 分段隧道和设计分级可见；任务输出含围岩等级及来源 |
| 支护 | 完成质量检查的支护步骤；另在 `/support-experiment` 查看参数化钢架与工作面 | 工作流给出支护结果；钢架几何可见且复用公共隧道，不重复下载隧道段 |
| 爆破 | 复位任务后进入 `/blast-twin` | 炮孔/点云可见，公共隧道仍只由一个 Viewer 承载 |
| 通风 | 进入 `/ventilation-twin`，切换到稳态 CFD 流线 | 通风模型、流线和图层可见；它位于另一个里程段，需切换视角，不与爆破断面强行重合 |
| 收尾 | 返回首页，重复上述切换 3 轮 | Viewer 实例 ID 不变；Canvas、事件处理器、任务资源引用与增强覆盖层回到稳定基线，无持续增长和控制台异常 |

若无法取得支护 API 记录，工作流应报告“证据不足”，不能把模型可见等同于支护质量合格。浏览器三维验收需要人工确认；`npm run test:scenario` 不启动 Cesium，也不能替代截图、交互和 GPU 生命周期检查。
