# 生命周期压力回归

日期：2026-10-12

## 目的与方法

在同一浏览器文档和同一 SPA 会话中，通过页面内导航依次访问业务模块，检查 Viewer、Cesium 场景对象、输入事件及资源引用能否在离开模块后恢复稳定状态。

本轮不使用地址栏跳转或重新加载路由，避免浏览器整页重载掩盖或干扰组件生命周期。采样来自开发态生命周期诊断器，每次切换后等待页面和资源状态稳定再记录。

## 初始首页基线

| 指标 | 初始值 |
|---|---:|
| Viewer 实例编号 | 1 |
| Canvas | 1 |
| Primitive | 8 |
| Entity | 3 |
| DataSource | 0 |
| 后处理阶段 | 0 |
| 活动输入处理器 | 3 |
| 活动资源 / 总引用 | 1 / 1 |
| JS Heap | 444,063,551 B（约 423.5 MiB） |

首页输入处理器 owner 为 `main.pointer-style`、`main.worksite-pick` 和 `viewer.debug-camera-position`；唯一活动业务外资源为应用级 `common.tunnel`。

## 跨模块压力流程

连续执行 5 轮以下页面内导航，共访问业务模块 15 次：

1. 首页 → 开挖爆破 → 首页
2. 首页 → 围岩支护 → 钢架试验 → 返回平台
3. 首页 → 通风除尘 → 首页

每轮返回首页后的结果：

| 轮次 | Primitive | 输入处理器 | 活动资源 / 引用 | JS Heap |
|---:|---:|---:|---:|---:|
| 1 | 8 | 3 | 1 / 1 | 约 444 MiB（首轮过程采样） |
| 2 | 8 | 3 | 1 / 1 | 452,965,885 B |
| 3 | 8 | 3 | 1 / 1 | 463,140,898 B |
| 4 | 8 | 3 | 1 / 1 | 547,177,872 B |
| 5 | 8 | 3 | 1 / 1 | 479,739,712 B |

爆破或支护刚返回首页时 Primitive 曾短暂为 `9`，随后在通风往返后回到 `8`；该值未随轮次持续递增。所有爆破、支护和通风资源离开模块后均为 `idle / 0`，应用级 `common.tunnel` 保持 `loaded / 1`。Viewer 实例编号始终为 `1`，Canvas、Entity、DataSource 和后处理阶段均保持基线，控制台无错误。

过程中 JS Heap 峰值约 735 MiB，之后能够回落；各轮稳定点不是单调增长。由于浏览器 GC 时机不可控，末次稳定点仍比初始值高约 52 MiB，因此本轮只能确认没有可见的结构性资源残留，不能单凭 Heap 快照断言不存在长期内存增长。

## 通风分析页签压力流程

在一次通风模块停留期间，连续执行 3 轮以下切换，共 12 次页签切换：

`CO 爆破扩散 → 瞬态通风 → 热瞬态分析 → 三维风流`

每个采样点均满足：

- 活动输入处理器为 3 个，owner 稳定为 `ventilation.camera-controls`、`ventilation.pick` 和 `viewer.debug-camera-position`。
- `ventilation.scene` 保持加载且引用数为 2；4 个分析子资源中始终只有当前页签对应资源处于 `loaded / 1`。
- 活动资源、已加载资源和总引用均为 3，无失败资源和控制台错误。

最后返回首页后，Primitive 恢复为 `8`，输入处理器恢复为首页的 3 个 owner，所有通风资源均为 `idle / 0`，只保留 `common.tunnel loaded / 1`；此时 JS Heap 为 496,012,021 B（约 473 MiB）。

## 结论与后续阈值

本轮通过了结构性生命周期检查：单 Viewer、场景对象数量、输入处理器 owner、活动资源和引用计数均未出现随切换次数累积的残留。

后续浏览器自动化应至少固化以下断言：

- Viewer 实例编号不变，Canvas 始终为 1。
- 返回首页后 Entity 为 3、DataSource 和后处理阶段为 0。
- 首页输入处理器恰好恢复为 3 个既定 owner。
- 业务模块资源全部为 `idle / 0`，仅 `common.tunnel` 保持 `loaded / 1`。
- Primitive 允许短时 `8～9` 波动，但不得按轮次持续增长。
- Heap 只作为趋势指标；应采用更长运行窗口、稳定等待和可控 GC 条件设定告警阈值，不作为单次硬失败条件。

## 增强应用/撤销补充回归

生命周期诊断新增以下增强指标：

- 活动 `EnhancementPlan` 数量。
- 冲突裁决后实际生效的增强指令数量与策略分布。
- 页面内 `[data-ventilation-enhancement]` 覆盖层 DOM 数量。

自动化测试对 `section`、`label`、`standard-view` 和 `chart` 四类高级适配器连续执行 25 轮应用/撤销，共调用 100 次适配器和 100 次逆序撤销。每轮撤销后活动适配器集合及全局增强诊断均精确恢复测试前基线。

真实浏览器在同一任务面板和同一 Viewer 中连续执行 5 轮“执行围岩评估 → 复位”：

| 状态 | Viewer | Primitive | Entity | 活动增强 | 活动资源 / 引用 |
|---|---:|---:|---:|---:|---:|
| 增强生效 | 1 | 首轮 17，后续稳定 21 | 20 | 1 个计划 / 4 条指令 | 2 / 3 |
| 复位完成 | 1 | 9 | 3 | 0 个计划 / 0 条指令 | 1 / 1 |

4 条生效指令稳定为 `visibility`、`highlight`、`label` 和 `standard-view` 各 1 条。每轮复位后通风覆盖层 DOM 为 0，`rock.design-grade` 回到 `idle / 0`，仅 `common.tunnel` 保持 `loaded / 1`；浏览器控制台无错误。

首轮增强状态的 Primitive 为 17、后续为 21，原因是公共隧道精细分段在首次任务定位后进入缓存；所有后续增强态保持 21，复位态保持 9，未出现逐轮增长。通风实际图表覆盖层和 Cesium 剖切对象的资源级集成回归仍列为下一项。
