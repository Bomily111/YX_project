# 智能体自然语言工具调用基线

日期：2026-10-12

## 环境

- 前端：Vite 开发服务器
- AI 后端：项目内 `backend` 服务
- Provider：Ollama
- Model：Qwen 2.5 7B
- 接口：`POST /api/ai-agent/chat`，SSE 流式响应

## 验证指令

> 请创建一个检查 DK278+330 至 DK278+340 初期支护质量的任务，先生成计划并等待我确认

## 验证结果

1. 模型发出真实 `create_task` 工具调用，而不是在文本中模拟调用。
2. 工具执行结果以标准 assistant tool-call 与 tool result 消息进入下一轮模型上下文。
3. 任务描述中的完整桩号被业务边界归一化为起点 `278330`、终点 `278340`。
4. 共享任务面板自动打开，生成 2 个工作流步骤与 2 份场景资源计划。
5. 任务状态为“待执行”，进度保持 `0/2`；“等待确认”的用户约束生效。
6. 第二轮模型正确读取任务 ID、步骤和资源预算，并向用户返回自然语言确认信息。
7. 工具内部 JSON 未直接混入最终聊天答复。

## 回归关注点

- 三类 Provider 的消息格式转换必须保留工具调用 ID。
- SSE JSON 跨网络数据块时不得丢失事件。
- 模型输出偏移量时，业务工具仍必须以任务描述中的完整桩号为准。
- 未得到明确执行指令时，不得调用 `execute_task_step` 或 `continue_workflow`。
