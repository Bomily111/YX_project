# 智能体施工场景装配与增强可视化开发计划

2026年11月13日经用户确认。本计划结合《硕士研究生选题报告》及本轮讨论，作为后续开发主计划。研究重点是施工任务下场景装配的准确性、真实性和美观性，以及任务驱动的自适应增强、二维三维协同和有文字依据的建议。现有取景、显隐、查询功能是执行基础，不能代表增强可视化方法已经完成。

## 用户确认的研究主线

用户在交接时进一步强调：目前基本所有装配场景都不够好看，优化范围必须覆盖全部已接入任务场景，不能仅改善三台阶和支护。近期优先开展全场景视觉质量整治，再以代表性样板验证增强方法。本文阶段1的三台阶/支护是首个样板，不是全部优化范围。

施工任务 → 任务相关资料与资源 → 校验并装配 → 识别视觉分析目标 → 增强规划与执行 → 场景反馈和有限调整 → 二维三维及文字依据协同 → 任务结论和具体建议 → 状态恢复与评价。

建议顺着原施工任务提出，回答本任务发现了什么、对应哪里、依据是什么、下一步核查什么。不能在装配后泛泛分析整个工程，也不能用视觉贴合推断工程配准精度或施工质量。

## 主流调度方式与本项目定位

本节纳入上一次关于主流智能体调度方式的讨论。通用架构采用受约束的智能决策与确定性平台执行；不要求所有平台使用同一种流程，也不把增加智能体数量作为目标。

| 官方资料中的模式 | 可参考的内容 | 本项目的对应实现方向 |
| --- | --- | --- |
| LangGraph工作流与智能体 | 预设流程与动态决策分开，路由、工具调用、任务分解、评价优化循环 | 固定装配前置校验与依赖执行，动态选择任务相关增强策略 |
| Anthropic智能体设计模式 | 串联、路由、协调执行、评价优化，以及读取环境反馈后继续行动 | 增强执行后读取真实场景反馈，判断调整、结束或恢复 |
| Microsoft Agent Framework | 顺序、并行、交接、动态协调，状态保存恢复与可观测能力 | 总体施工分析流程受控，需推理的步骤由智能体参与，记录状态与执行结果 |

参考官方资料：[LangGraph](https://docs.langchain.com/oss/python/langgraph/workflows-agents)、[Anthropic](https://www.anthropic.com/research/building-effective-agents)、[Microsoft](https://learn.microsoft.com/en-us/agent-framework/journey/workflows)。上述模式是技术基础，不直接等于本论文创新。拟研究贡献应通过文献比较与实验论证任务与视觉表达映射、场景反馈约束、策略组合以及认知效果。

起步采用一个主智能体配合资源管理器、增强执行器和反馈评价模块。后续确有独立任务和收益时再考虑多智能体；共享Viewer的相机、显隐、剖切写操作需协调，不能任意并行执行。

## 决策与执行职责

| 职责 | 智能体 | 平台 |
| --- | --- | --- |
| 任务理解 | 识别施工目标、分析步骤、重点对象、所需证据 | 校验结构、里程、资料范围与必要条件 |
| 场景装配 | 选择已有资源及其任务用途 | 依赖加载、中线定位、几何与兼容检查、失败处理 |
| 增强规划 | 依据任务和当前场景选择策略组合并说明理由 | 检查适用对象、参数范围、策略冲突和执行顺序 |
| 增强执行 | 根据执行结果决定下一步 | 确定性改变显示、计算几何、更新图表并记录实际生效值 |
| 反馈评价 | 解释反馈，选择继续调整、结束或说明限制 | 计算画面指标、核对资源与资料状态，控制迭代上限与恢复 |
| 建议输出 | 组织任务结论和可操作建议 | 提供可追溯对象、数值和文字引用，区分已核实与未核实 |

模型调用成功、模型ready、画面可辨认和工程判断成立必须分别记录。不得由智能体自行声称几何检查或质量核查通过。

## 任务与资料结构

在现有任务上下文基础上增加视觉任务描述：施工目标、里程范围、判断步骤、目标对象、对象关系、必要参照、所需证据、预期回答的问题及完成条件。具体字段在实现时与现有上下文兼容，避免重复建立互相矛盾的任务状态。

按里程、时间、版本和适用范围关联设计说明、施工方案、地质记录、监测报告、巡检记录和技术交底。检索结果保存文件、章节或页码以及原文片段；引用编号由平台分配，模型不能自行编造。资料之间或资料与模型冲突时显示矛盾和待核查项。单一测试工段可以示意装配异来源资料，但必须保留来源与非实测对应说明。

## 增强可视化方法

建立任务—工程对象及其关系—视觉表达的映射。区分位置、包含、地质与支护对应、设计与实测差异、监测数据与测点关联、工序先后等关系。相同模型组合可以因施工交底、布置核对或差异分析而采用不同策略。

| 增强目的 | 计划能力 | 约束 |
| --- | --- | --- |
| 内部结构辨识 | 局部透明、剖切、轮廓保留，必要时提供示意分解 | 不破坏装配基准；分解或位移须明确标为表达状态 |
| 空间与工序关系 | 区段编码、距离尺寸、开挖方向、施工阶段表达 | 位置和数值来自模型或资料，示意值单独说明 |
| 设计实测对比 | 同位置对照、差异场着色、断面对比、偏差图表 | 必须有可比较的数据及对应基准；无实测不生成偏差结论 |
| 视觉注意引导 | 重点区域突出、背景层次弱化、分步骤引导 | 保留必要参照，避免多个目标同时过度突出 |
| 来源与不确定性区分 | 区分设计、实测、解释和示意数据 | 编码与图例一致，不把视觉颜色直接当作工程风险等级 |
| 连续分析 | 重点随步骤变化，保留前序证据与结果，支持恢复 | 保存增强前状态，明确当前步骤及恢复范围 |

增强策略应形成可组合、可恢复的策略目录，描述适用任务、输入对象、数据条件、受控参数、预期效果、冲突和撤销方式。现有工具接入该目录，避免以新增按钮数量代替方法研发。

执行闭环为：确定视觉目标 → 产生有限候选策略 → 平台校验 → 执行 → 获取实际反馈 → 按完成条件结束或在预算内调整。起步使用规则约束与有限候选组合，不先引入无约束反复试错。

反馈包括目标是否进入画面、尺度是否足够、遮挡及密集干扰、必要参照是否可辨认、标签重叠、颜色区分、二维关联一致性和资料充分性。可先以屏幕范围和采样近似测量，再核验测量适用性；包围球入镜不代表真实无遮挡。指标阈值、调整上限及降级策略在试验前通过样例确定并记录，不能在看到结果后随意改变。

## 二维三维与文字依据协同

二维信息补充三维不便准确表达的量值与比较，按任务生成，不默认堆叠所有图表。三维对象、图表记录和文字依据通过同一对象标识、里程、时间与数据版本关联。

支护任务首先提供工段纵向布置图、参数对照表和引用摘要；后续按资料条件扩展断面对比、偏差曲线、监测时序和通风工况图。二维选中位置定位三维对象，三维选择同步定位图表与文字记录，步骤或工段变化共同更新。表格区分设计要求、当前装配值、实际观测值和核对条件，缺失项不能填成零或通过。

建议区分资料记载、数据/场景所反映的现象以及综合建议。每条建议关联本任务判断步骤、位置或对象、证据引用和具体下一步动作；资料不足列为待核查，不将示例参数当作现场施工结论。

## 当前状态与待开发边界

现有基础包括受控资源装配、来源记录、部分失败处理、相机/显隐/剖切等算子、支护构件查询与控制、后续类型/长度调整和显隐承接、模块切换清理及爆破单段加载。分项页面测试不等于全部模型或所有施工任务已经验收。

尚需重点实现：完整场景几何与视觉验收、视觉任务建模、场景反馈测量、策略规划与调整、二维三维关联、文字依据引用、任务建议和认知效果实验。通用当前装配自检只进行了检查准备，不能记为已实现。掌子面贴图载体仍需完善。Z-PM保留源资料不完整和构件间距未核验的边界。

## 开发顺序与阶段交付

开始阶段1前先形成全场景巡检台账。对现有可运行任务逐一在真实页面截图，记录实际使用的模型及来源、默认取景、几何问题、遮挡、材质/配色、背景干扰、二维布局及修复优先级。至少覆盖下表；某类缺可用数据时明确标注，不能用另一类型的截图代替。

| 场景类别 | 首轮重点检查 |
| --- | --- |
| 三台阶与不同类型支护 | 几何衔接、重复端面、密集配筋、外壳遮挡、材质和构图 |
| 掌子面与支护/水平钻 | 照片载体突兀、洞壁衔接、相互位置、钻孔辨识和二维信息布局 |
| 围岩解释与支护 | 体数据遮挡、色标及来源区分、剖切边界、必要空间参照 |
| 爆破点云与炮孔 | 密集点线干扰、设计与爆后结果区分、轮廓和取景 |
| 爆破与通风组合 | 点云与流线竞争、风场编码、重点区域及图例一致性 |
| 掌子面与GPR及已接入通风工况 | 三维载体与二维图表关联、面板遮挡、图表尺度与任务重点 |

巡检后先处理跨场景共性问题：模型材质和强调色语义、透明度与深度关系、背景层次、光照、相机与界面安全区、图例和图表样式。保持同一Viewer和平台界面，不以额外展示背景替代统一场景；背景弱化等操作必须受控、可恢复。语义色标不得为美观随意改写，原始资产保留。

然后处理各模型和场景特有问题。每类提供相同任务、资产、视角条件下的前后对比，并分别记录准确性、真实性、美观性和信息辨识结果。用户对当前总体效果不满意的状态继续保留，不能以历史测试通过或一张新截图将整类场景标记为完成。暂缓继续堆叠零散工具入口，以场景效果改进和可验证的增强方法为主要交付。

| 阶段 | 工作与交付 | 进入下一阶段的检查 |
| --- | --- | --- |
| 1 场景真实性基线 | 以测试工段完成三台阶与后方支护的空间、接缝、标高、方向、材质和遮挡检查，形成源数据及几何核查清单 | 整体、侧面、近景截图与实际结构核查；问题有修复或明确边界，不用增强掩盖错误装配 |
| 2 任务与证据组织 | 结构化视觉目标、判断步骤、重点/参照关系和文字证据；建立只读装配反馈 | 同一模型组合的不同施工任务产生不同的分析目标，引用可定位到真实资料 |
| 3 受控增强与反馈 | 策略目录、参数/冲突检查、实际生效状态、反馈指标、有限调整与恢复 | 能解释选择依据，识别执行无效和遮挡未解决，避免无限循环 |
| 4 首个完整样板 | 三台阶与后方支护交底/布置核对，联动纵向布置图、参数表、文字依据及任务建议 | 完成下述五步骤闭环，新增缺失数据不冒充实测 |
| 5 任务推广与稳定性 | 按资料条件扩展地质与支护、掌子面探测、爆破/通风；连续切换与释放测试 | 几何、来源、图表、引用及视觉状态不串用，记录运行开销和异常 |
| 6 论文实验与材料 | 固定任务集、对比/消融实验、指标结果、配图和可复现步骤 | 评价用户理解与操作效果，区分方法建议、系统实现和实测研究结论 |

各阶段可交叉迭代，但后续展示功能不能替代阶段1的场景质量验收。支护优先复用已有模型，不擅自生成替代构件；缺失资料与几何不足显式记录。掌子面仅任务需要照片时装配一张对应载体，后续完善其轮廓、边缘与洞壁衔接。

首个样板按五步组织：整体工段理解 → 交界区空间核对 → 构件布置核对 → 对应文字/数据依据核对 → 整体回看及任务建议。每步保留必要参照与前序结果，避免步骤切换覆盖分析依据。

## 实验与评价

沿开题报告比较人工操作、自主装配、自主装配并增强三种条件。单独评价增强贡献时控制相同任务、资产与装配结果；比较任务耗时、切换次数、关键对象识别正确率、信息理解以及交互负担。记录参与者条件与学习顺序影响，具体样本与指标在试验设计时确定，不预先宣称有效。

分别去除遮挡处理、重点标识或二维联动进行消融。系统层面记录资源选择/定位正确性、加载成功、重复/错误调用、反馈调整次数、恢复正确性和运行开销。准确性、真实性、美观性、可读性与工程结论分别评价；通过截图、几何检查和用户任务实验共同形成证据，不用自动化成功率替代认知效果。

## 持续约束

同一Viewer与测试工段优先；保留已有模型和所有既有未提交修改。文字证据围绕原施工任务，增强不能改写源数据。长期历史、跨刷新恢复等仍按用户决定暂缓；当前任务的状态传递、来源关联与增强恢复属于本计划必要能力。
