# 三台阶与后方连续支护测试工段

本页为已撤下的自建支护历史方案。用户要求直接调用已有模型后，运行实现已替换为原始ZZ-Va GLB的刚性副本，详见[修正记录](development-2026-11-11-existing-support-correction.md)。不得用本页自建壳体/拱肋描述当前支护。

在用户已确认的论文统一测试工段YK2+244，新增同源连续支护实体并开放成对调度。没有把旧ZZ-Va模板平移后强行叠到三台阶上。

## 模型与空间关系

从实际 `tunnel002.glb` 再提取源局部X=118至128的11个洞内截面，沿轮廓生成连续壳体，配置10道示意拱肋。新增资产与其他隧道模型同目录：

- `public/data/tunnel/测试工段支护.glb`
- `public/data/tunnel/测试工段支护.blend`
- `public/data/tunnel/测试工段支护.metadata.json`

生成脚本为 `scripts/build-test-section-support.py`。截面源数据由既有提取脚本生成，新增 `supportSections`，原三台阶断面数据保留。

两模型共用原点与源隧道运行时变换。以三台阶下台阶后缘为局部轴向0：支护占[-10,0]，三台阶剩余岩体占[0,22]。支护末端与下台阶后缘接合，不把整个支护段插进未开挖岩体。壳体使用透明材质以查看拱肋；未拉伸单断面，也未堆叠密集锚杆。径向壳厚0.26米、拱肋间距1米和简化截面均为演示参数，不声称属于ZZ-Va工法设计。源局部坐标距离并非精确沿中线施工进尺，YK2+244是测试入口标签。

## 调度

新增资源 `support.test-section`，可单独展示或与 `rock.three-bench` 组合。明确需要三台阶与后方支护的任务才选两项，不默认给单模型请求加支护。组合支持两个顺序，统一完成装配后再增强。旧支护类型、照片或其他解释层与这对模型的空间关系未校核，仍拒绝混装，不自动填充场景。

最终镜头按两模型合并包围球取景；外部主隧道降透明，保留共同位置参照。整体视角也包含两者。两模型分别保留加载、取消、卸载、来源元数据和实际文件指纹。
