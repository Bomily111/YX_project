## 1. 项目目标与当前结论

- 项目位于 `D:\project`，前端为 Vue 3 + Cesium + ECharts，后端为 Express + PostgreSQL；目标是围岩、爆破、支护、调度、通风五类模块在单一 Viewer 上由任务/智能体按需组合、增强、执行、回滚和留痕。
- 已有自然语言调用在线 Ollama/Qwen 工具的第一版闭环。`compose_scene_workflow` 可以从受控资源中生成围岩 → 支护 → 爆破 → 通风等分阶段动态场景计划；**生成后由用户确认执行**。`create_task` 则进入带业务动作的任务工作流，二者不要混为“模型已自动完成工程判断”。
- 当前可用数据以示例/局部数据为主，重点验证动态编排、空间展示和资源生命周期，不能声称五类数据已经完成统一工程时空配准或联合工程结论。
- 用户最新决定：**模型等资源资产整理入 PostgreSQL 可以后置**。已有数据库表和哈希清单，当前不要因资产入库阻断平台后续研发；未来宜入库资产元数据/版本/来源/配准信息，GLB、点云、CFD 大文件仍在文件存储。

## 3. 关键边界与已知问题

1. **通风展示只是示意配准。** 原始 CFD 数据属于 K3+805～K4+005；当前代码把一条主洞约 200 m 的直线段显示中心投影到 DK278+330 中线附近，保留原数据直线形态及双洞间距。这不是 DK278+330 的实测风场，不能据此与围岩、爆破、支护作同址联合工程判断。配准实现见 `src/views/ventilation-module/spatialFrame.ts`。
2. **支护钢架是参数化示例。** 可用于展示/生命周期验证，不能把钢架可见直接判定为现场支护质量合格。质量检查若缺少支护 API 证据，应明确“证据不足”。
3. **CFD 原始数据有元数据不一致。** `cfd_cell_data_lite.json` 的 `meta.n=6785`，采样数组长度为 6786；测试将其列为已知预期失败。未取得可靠原始导出前，不应随意删改采样值使测试变绿。
4. **文案/文档有旧表述。** `docs/agent-dynamic-scene.md` 仍写通风在独立里程局部展示，任务面板成功提示也仍写“仅分阶段展示”；它们需与现行“示意配准到 DK278+330、但非实测同址”的准确措辞同步。当前 `src/ai-agent/tools/workflow.tools.ts` 与配准代码较新。
5. **调度尚未作为正式任务资源完成。** 原有人员、设备、甘特图组件可用，但 `src/modules/dispatch/resources.ts` 尚不存在；施工组织、通风风险处置两类正式业务动作仍待补齐。
6. 历史快照只读回看已完成第一版；通风额外工况/热场时间切片、支护参数化 Blob、调度 API 的“实际使用版本”仍未完整追踪。不要宣称跨版本三维重建已实现。

## 4. 建议新对话首先做的任务

**优先完成最新一轮改动的真实页面视觉验收，而不是立即做资产入库。**

1. 在当前前后端环境可用时，打开首页，通过智能体生成“依次展示 DK278+330 附近围岩、支护、爆破、通风”的场景计划。检查围岩 → 支护第二阶段的同屏效果、通风直线场在工点中线附近的镜头与来源提示，并复位。
2. 每阶段核对实际 Cesium 画面及 `window.__DT_PLATFORM_DIAGNOSTICS__?.()`：Viewer/Canvas 不重复、资源引用和增强指令在复位后归零、无控制台异常。保留必要截图；仅自动化几何测试不能代替视觉验收。
3. 若画面符合预期，顺手统一第 3 节第 4 项的过时文案和说明，并补一条视觉验收记录；若不符合，先修空间位置、相机或生命周期问题，再进入下一项研发。

随后按开发计划继续：补施工组织/通风风险处置业务动作与调度资源；完善实际资产版本追踪和历史三维重建边界；再做时间维、差异增强、消融开关与论文实验指标导出。资产目录入库可在这些工作的合适节点实施，不是当前首要阻塞项。
