# 通风资源拆分（第一版）

更新日期：2026-10-12

## 资源边界

通风模块不再把模型与全部分析数据视为一个聚合资源，而是分为一个基础场景和四个分析子资源：

| 资源 ID | 职责 | 主要数据/对象 |
|---|---|---|
| `ventilation.scene` | 公共通风场景 | 通风专用 GLB、公共隧道显隐状态 |
| `ventilation.steady-cfd` | 稳态风场 | CFD 单元、风向矢量及对应图层 |
| `ventilation.co-analysis` | 爆破后 CO 扩散 | CO 时空分析结果 |
| `ventilation.transient-network` | 瞬态通风网络 | 默认风机升速工况 |
| `ventilation.thermal-field` | 瞬态热场 | 热场索引、监测点和当前热场图层 |

四个分析资源都显式依赖 `ventilation.scene`。基础资源只负责模型和公共场景状态；分析资源负责自己的数据缓存与可视对象，卸载时清空缓存，并由拥有图层的资源删除对应 Cesium 图层。

## 页签切换生命周期

进入通风模块时，页面先显式持有一次 `ventilation.scene`。选择分析页签时，按以下顺序执行：

1. 释放当前分析资源；其基础场景依赖引用同时减一。
2. 加载目标分析资源；ResourceManager 自动增加基础场景依赖引用。
3. 从资源缓存读取数据，再构建页面图层或图表。

离开模块时，页面一次释放“当前分析资源 + 基础场景”。ResourceManager 按依赖逆序卸载，最终销毁通风专用对象并恢复进入模块前的公共隧道显隐状态。这样既不会在页签间重复加载 GLB，也不会让已离开的分析数据继续占用内存。

## 二级按需数据

本轮资源拆分以分析类别为边界，仍保留两类更细粒度数据的按需请求：

- `ventilation.transient-network` 预载默认 `fan_ramp_up` 工况；用户选择其他瞬态工况时再读取对应文件。
- `ventilation.thermal-field` 预载时间索引和监测序列；用户切换时间步时再读取该时刻的热场切片。

这些请求属于已加载分析资源内部的二级数据，不要求在进入通风模块时一次性下载。后续若需要跨任务缓存或精确的切片级内存预算，可再将它们提升为独立资源。

## 接入约束

- 新增分析页签必须声明独立、稳定的资源 ID，并依赖 `ventilation.scene`。
- 页面不得再次直接预载整类分析数据；首屏所需数据应由资源 `load` 提供。
- 子资源卸载必须清除自身缓存及其创建的 Cesium 对象，不能销毁基础 GLB。
- 剖切、图表等任务增强应继续通过资源目标适配器接入，避免平台执行器感知页面内部对象。

## 任务增强适配

四个分析子资源已经声明第一版任务增强目标：

- 稳态 CFD：在任务里程处应用模型剖切，撤销时恢复原 `ClippingPlaneCollection`。
- CO 扩散：根据资源缓存生成浓度—时间覆盖图。
- 瞬态网络：根据默认工况生成网络流量覆盖图。
- 热场：同时提供任务里程剖切和出口温度覆盖图。

图表由资源适配器挂载到当前 Viewer 容器，增强复位时销毁 ECharts 实例、移除窗口事件和 DOM 节点。图表目标没有伪造 Cesium 对象；增强规划器只会对真正声明 `object` 的目标生成显隐、透明度或轮廓指令，纯图表目标只执行其 `chart` 适配器。
