# 增强可视化执行器（第一版）

更新日期：2026-10-12

以下描述现有增强引擎及其逐阶段事务接入方式。论文场景任务的目标执行时机已确定为**完整场景构建并校验之后**；现有引擎将作为构建后增强的执行基础，流程差距见[构建后增强架构约定](post-assembly-enhancement.md)。

## 计划生成

`EnhancementPlanner` 在资源加载完成后读取 `SceneResource.getEnhanceTargets()`：

- 重点资源：保持可见，应用任务轮廓高亮。
- 必要参照与依赖资源：保持可见，应用低透明度表达。
- 排除资源：不产生增强指令。

`EnhancementPlan` 只保存资源 ID、目标 ID、策略、冲突组、优先级和参数，不直接保存 Cesium 对象，因此可以记录、比较和复现。运行时由 `EnhancementEngine` 从资源注册表重新解析目标对象。

## 冲突规则

冲突按“资源 + 目标 + 冲突组”独立裁决。组内优先级较高的指令生效，其他指令记录为 `suppressed` 并保存胜出指令 ID；同优先级使用稳定指令 ID 排序，保证重复运行结果一致。

当前约定的优先级包括：

| 策略 | 冲突组 | 默认优先级 |
|---|---|---:|
| 显隐 | visibility | 90 |
| 剖切 | occlusion | 80 |
| 风险固定色 | color | 高于普通任务高亮 |
| 任务轮廓高亮 | color | 60 |
| 参照透明度 | occlusion | 40 |

因此同一目标存在剖切与整体透明时，剖切胜出；风险色和任务高亮同组时，风险色应使用更高优先级。

## 状态快照与恢复

每个策略处理器在写入目标前读取原始属性，并返回独立的撤销函数。计划复位时按指令应用的逆序执行撤销。应用新计划前先恢复旧计划的原始状态；若新计划中途失败，先撤销已应用的新指令，再重新应用上一计划。

平台内置以下处理器：

- `visibility`：保存并恢复 `show`。
- `opacity`：支持直接 `opacity` 属性或带 `alpha` 的 `color`，保留原颜色对象。
- `highlight` / `risk-color`：保存并恢复 `silhouetteColor` 与 `silhouetteSize`。
- `section`、`label`、`standard-view`、`chart`：委托给资源目标声明的适配器执行，平台统一传递参数并登记撤销函数。

高级策略采用资源侧适配器，而不是由执行器猜测页面内部对象。`EnhanceTarget.adapters` 声明实现，`recommendedEnhancements` 声明当前目标真正需要的表达；两者同时存在时规划器才生成指令。默认优先级为剖切 80、标准视点 70、标签 55、图表 50。资源适配器必须先保存原状态并返回撤销函数。

`rock.design-grade` 是首个实际适配：任务命中的围岩分段推荐标准视点和标签。标准视点保存相机位置、方向和上方向后定位到分段包围球；标签保存原显隐状态。任务切换或复位时二者均恢复。

通风分析资源已接入第二组实际适配：稳态 CFD 与热场可应用任务里程剖切，CO、瞬态网络与热场可在 Viewer 容器生成 ECharts 覆盖层。剖切恢复原裁剪集合；图表撤销时同时释放图表实例、DOM 和窗口事件。没有 `object` 的纯 UI 增强目标不会生成显隐、透明度或轮廓指令。

开发态诊断会汇总所有当前生效的增强引擎，记录活动计划数、冲突裁决后实际生效的指令数、各策略数量以及通风图表覆盖层 DOM 数量。引擎在新计划替换、失败恢复和复位时同步更新登记，使浏览器回归可以直接断言增强是否完全撤销。

## 与工作流事务集成

启用增强选项的 `withScenePlan` 会在场景切换前先撤销旧增强，防止资源卸载后再访问已销毁的 Cesium 对象。新资源加载完成后才生成 `EnhancementPlan`，保证 `getEnhanceTargets()` 返回的是当前有效对象。

若增强失败，适配器会撤销部分视觉修改、恢复旧场景并重新应用旧增强，业务动作不会开始。若业务动作或后续步骤失败，则按业务副作用、当前增强、当前场景、旧增强的顺序回滚。这个顺序保证视觉处理器始终只操作仍然存活的资源对象。
