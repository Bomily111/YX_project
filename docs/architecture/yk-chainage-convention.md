# YK 中线里程约定（2026-10-21）

平台任务、场景资源覆盖范围、智能体调度结果与主界面里程均以 `src/assets/data/centerline_mileage.json` 的 YK 实测中线为准。内部数值是 YK 绝对米数，例如 `YK2+244 = 2244`。相机位置使用 `ChainageService.positionAt(2244)`，不再查粗略里程坐标表。

| 来源 | 处理方式 | 示例 |
| --- | --- | --- |
| YK 实测中线 | 唯一任务基准，直接使用 | `YK2+244 → 2244` |
| 旧 DK 标签 | 只在用户输入和历史接口边界兼容换算；不进入任务内部 | 旧 `DK278+330 → YK1+346`；旧 `DK279+228 → YK2+244` |
| 通风局部 K | 原始 CFD 数据坐标，保留在数据/截面参数；任务登记示意投影的 YK 范围 | 局部 `K3+805～K4+005` 示意投影到 `YK1+246～YK1+446`，中心 `YK1+346`；不是该处实测风场 |
| X1DK 报告 | 独立工程来源，不凭数字偏移合并到 YK | TSP 来源报告 `X1DK2+937`；四类解释体在平台的示意锚点仍为 `YK2+244` |

造成冲突的旧实现有三处：资源表把设计围岩/支护/爆破写成 DK 数值，却把物探体写成 YK 数值；通风任务范围直接使用局部 K；旧智能体飞行工具使用另一片区域的硬编码 DK→经纬度假表并回退到最近示例点。现统一资源任务范围和飞行入口到 YK。围岩质量检查只采纳明确标记为 YK 的掌子面记录，避免将独立工程 X1DK 素描仅按相同数字误作本工点证据。旧支护数据库字段 `start_dk/end_dk` 在读取边界换算；新任务结果节点写入 `workflowState.chainageFrame: YK`，历史面板把无标记旧节点提示为里程体系未确认，不能当成新的 YK 任务直接重放。

当前四类围岩解释资源都在 YK2+244 附近，按阶段切换。它们与设计隧道共享显示中线，但不同来源报告是否对应同一实测工点，需要现场测量和来源核验；里程格式统一不等于科学数据已融合。
