# 场景资源选择（第一版）

更新日期：2026-10-11

## 选择边界

工作流先确定当前 `TaskStep`，资源选择才开始运行。默认候选集只包含当前步骤所属模块的资源，跨模块参照必须由模板或智能体显式提供候选资源 ID，避免相关度分数反过来组织整个任务流程。公共资源不参与评分，只作为业务资源依赖进入加载顺序。

## 固定相关度配置

```text
taskRelevance = clamp(
  0.35 × typeMatch +
  0.30 × mileageMatch +
  0.20 × processMatch +
  0.15 × stateMatch,
  0, 1
)
```

- `>= 0.70`：重点资源。
- `0.35–0.69`：必要参照。
- `< 0.35`：排除。

类型、里程、工序和状态的分项得分及文字理由均进入 `ScenePlan`。权重必须为非负有限数且总和为 1，阈值必须满足 `0 <= reference <= focus <= 1`。计算完全由确定性规则完成，不调用大模型。

里程匹配使用“资源与任务交集长度 / 任务区间长度”。没有里程范围的资源视为全局可用；没有指定工序或目标状态表示该条件不构成限制。当前各模块仍存在平台里程与局部工程坐标并存的问题，因此局部坐标资源后续应在模块清单中补充可比较的统一里程范围。

## ScenePlan 内容

- `rootResourceIds`：交给 `ResourceManager.load/release` 的业务根资源。
- `loadOrder`：注册表解析出的依赖优先完整顺序。
- `releaseResourceIds`：相对上一计划不再需要的根资源。
- `decisions`：每项候选的分级、得分、分项得分、理由和内存估算。
- `estimatedIncrementalMemoryMb`：排除已加载资源和共享依赖后的新增内存估算。
- `relevanceConfig`：本次实际使用的权重和阈值快照。
- `warnings`：内存预算淘汰或无可用资源等需要界面提示的信息。

资源按相关度降序、稳定 ID 升序选择。达到任务 `maxLoadMb` 限制后，后续资源标记为排除并保留原因，而不是悄悄消失。这样相同任务、候选资源和配置会得到一致的选择结果。

## 事务执行

`ScenePlanExecutor` 是 `ScenePlan` 与 `ResourceManager` 之间的唯一事务入口。切换计划时先加载和激活新增根资源，再更新保留资源，最后释放旧根资源。这个顺序保证新旧计划共享的公共依赖不会在切换中被暂时卸载。

加载新资源失败时不修改旧计划；释放旧资源失败时重新取得旧资源引用并激活旧任务上下文，再撤销新增资源。`clear()` 释放失败时同样尝试恢复原计划。活动计划只在全部操作成功后提交。

`withScenePlan` 将资源事务和增强事务一起包装进 `WorkflowExecutor` 的动作处理器。正向顺序固定为“加载资源 → 应用增强 → 执行业务动作”，回滚顺序固定为“清理业务副作用 → 恢复视觉状态 → 恢复场景资源 → 重建原视觉状态”。增强应用失败时不会调用业务动作；业务动作中途失败、后续步骤失败或整个工作流复位时，资源和视觉效果均恢复到步骤开始前。
