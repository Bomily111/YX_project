# 任务运行与工具调用审计

日期：2026-10-17

## 记录范围

`task_runs` 保存经校验的任务上下文、初始工作流计划、初始场景计划和当前运行状态。`task_audit_events` 保存面板和智能体两种入口的事件，按自增 ID 保持读取顺序。`task_run_snapshots` 在计划生成、每步结束、重试和复位后追加不可变结果节点，包括工作流步骤/共享上下文、实际活动 ScenePlan、EnhancementPlan、任务场景资源状态和已读取数据的内容指纹。复位不会删除此前的结果节点。

面板生成计划后创建运行记录；逐步执行、连续执行、失败重试和复位会写入事件。步骤事件包含输入摘要、输出值及来源元数据、耗时、错误和回滚状态。自然语言工具由浏览器执行，Agent 界面在工具返回后另写一条含工具调用 ID、参数摘要和结果摘要的事件。两种入口使用同一个任务 ID，便于合并分析。

审计参数限制嵌套深度、数组长度与字符串长度，并遮盖密码、令牌和 API Key 字段。聊天原文和模型响应全文不进入本表。审计存储失败会在任务面板或 AI 助手显示警告，不把已经完成的业务步骤错误地标记为失败。

## 部署与查询

在后端目录执行 `npm run db:task-audit`，将 `003_task_audit.sql` 应用到当前 PostgreSQL。脚本使用现有后端 `.env` 数据库配置，重复执行安全。随后重启后端进程以加载新路由。

- `GET /api/ai-agent/task-runs?limit=30`：最近的任务运行摘要。
- `GET /api/ai-agent/task-runs/:taskId`：任务上下文、初始计划和按 ID 排序的事件。
- `GET /api/ai-agent/task-runs/:taskId/snapshots`：按 ID 排序的结果节点。
- `POST /api/ai-agent/task-runs`、`POST /api/ai-agent/task-events`、`POST /api/ai-agent/task-snapshots`：前端写入入口。

任务面板的“历史结果回看”只读呈现保存的结果和步骤状态，不重新执行工作流，也不恢复旧 Cesium 对象。围岩设计分级 JSON、内置掌子面记录及支护 API 映射后的记录在业务动作实际读取时计算规范 JSON 内容指纹，优先 SHA-256；非安全 HTTP 环境缺少 Web Crypto 时退化为 FNV-1a 64 位并标明算法。指纹能识别这三类业务输入是否变化，但不是文件原字节哈希，也不封存原始数据；尚未读取的来源没有指纹。

`npm run assets:manifest` 对 17 个公共隧道分段、爆破 GLB、通风专用 GLB，以及通风分析 JSON 和三张结果图共 40 个文件流式计算 SHA-256 字节哈希，生成 `public/data/task-asset-manifest.json`。`npm run assets:check` 校验清单是否与本地文件一致，生产构建会先运行该校验。资源可通过 `getActiveAssetPaths()` 报告当前实际使用的静态文件；结果快照仅为活动场景中已加载资源报告的文件关联清单指纹，不根据模块名称推测。当前质量检查流程使用公共隧道分段；爆破和通风资源的报告接口已就绪，待相应任务执行链接入后进入快照。清单不可用时只提示，不将未知资产伪装成已验证。此清单证明构建时本地文件版本，不直接校验浏览器实际下载的响应字节。支护参数化 Blob 模型与通风页签额外按需读取的工况/时间切片尚未动态报告，不能据此重建或证明整个三维场景完全一致。三维视觉重建、其余数据版本固定及实验 CSV 导出仍需后续实现。当前部署沿用项目现有的 API 访问控制设置；面向多人实验开放时，需要按用户或实验会话限制查询范围。

## 验证

本地 PostgreSQL 已应用迁移。通过真实后端 API 创建临时任务、写入“步骤完成”和“复位”两个节点并读回，确认复位后仍可读取旧节点，随后删除临时记录。前端类型检查、自动化测试和生产构建作为回归门槛。
